## หลักการนำเข้า

- แถวที่มีรหัสเลขในคอลัมน์ A เป็นงานหลัก ส่วนงานโครงสร้างพื้นฐานที่มีสถานะใน C แต่ไม่มีรหัสเลข (ระบบระบายน้ำ 2 / ถนน 2) เป็นงานหลักเช่นกัน
- แถวรายละเอียดใน B ใต้แต่ละงานหลักเป็นงานย่อย เก็บแถวซ้ำที่ต้นฉบับมีอยู่ เช่น งานเจาะผนัง 2 แถวของ C12 ไม่รวม/ตัดทิ้งเอง
- แถวหลังหัวข้อ `ตารางงานเพิ่มเติมสำหรับวิลล่า` เป็น Extra รวม 4 งานหลักต่อวิลล่า 12 หลัง = 48 งานหลัก ไม่ตีความงานทั้งหมดที่มีคำว่า “ต่อเติม” เป็น Extra
- เก็บชื่อชีตและหมายเลขแถวของทุกงานไว้ในข้อมูลสำรองและแสดงในเช็คลิสต์ เก็บสถานะดิบและเปอร์เซ็นต์ของงานหลักจากต้นฉบับแยกจากสถานะที่ผู้ใช้เปลี่ยน
- “เสร็จ” / “เสร็จสมบูรณ์ 100%” = เสร็จแล้ว, “กำลังดำเนินการ” = กำลังทำ, “ที่เหลืออยู่” / “ความคืบหน้า 0%” = ยังไม่ได้ทำ, ว่าง = รอยืนยัน โดยไม่อ้างว่าเริ่มหรือเสร็จแล้ว
- ไม่ถ่ายทอดเปอร์เซ็นต์ของงานหลักไปยืนยันว่างานย่อยใดเสร็จแล้ว หากงานหลักเสร็จแต่ช่องสถานะย่อยว่าง จะคงช่องย่อยไว้รอยืนยันตามต้นฉบับ จนกว่าผู้ใช้ยืนยันเอง
- มีข้อมูลเริ่มและระยะเวลาที่เป็นข้อความชัดเจนเฉพาะงานย่อยบางรายการของ B8 เก็บวันที่เริ่มจาก D และระยะเวลาจาก E วันสิ้นสุดคำนวณ = วันเริ่ม + (จำนวนสัปดาห์ × 7) − 1 แสดงว่าเป็น “สิ้นสุดคำนวณ” ไม่ใช่กำหนดส่งที่ยืนยันแล้วหรือวันเสร็จจริง
- ไม่แปลงสี/รูปทรงใน Gantt เป็นสถานะจริงหรือกำหนดเสร็จ เพราะไม่มีคำอธิบายเพียงพอ ไม่กรอกกำหนดเสร็จของงานหลักจากปฏิทินหรือกำหนดงานย่อยที่มีเพียงบางส่วน
- ไม่สร้างเหตุผล ผู้ขอ วันที่ขอ ผู้รับผิดชอบ ราคาหรือวันเสร็จจริงที่ไม่มีในต้นฉบับ มูลค่า Extra ใช้ `amountKnown: false` เพื่อแยกจากการระบุ 0 บาท
- หมวดงานจัดจากชื่อขอบเขตเพื่อใช้กรอง ส่วนชื่อขอบเขตเดิมคงอยู่ครบ
- Matrix รวมขอบเขตรั้วที่ชื่อแตกต่างเพราะมีเลขบ้านด้วย `matrixKey` ชื่อต้นฉบับในเช็คลิสต์ยังคงเดิม
- เทมเพลตเป็นคลังงานตามสัญญา 27 แบบ เก็บชุดรายละเอียดที่ต่างกันเป็นคนละแบบ ไม่รวมจนสูญเสียขอบเขตงาน และไม่ใช้รายการ Extra เป็นเทมเพลตมาตรฐาน

## การอัปเดตข้อมูลในเบราว์เซอร์

ใช้ localStorage key เดิมเพื่อรักษาข้อมูลผู้ใช้ที่มีอยู่ ผู้ใช้ใหม่เริ่มด้วยแผน R3 ผู้ใช้เดิมต้องเลือกโหลดแผนเองหลังยืนยัน การโหลดเก็บข้อมูลเดิมใน localStorage อีกช่องและสร้างไฟล์ JSON ดาวน์โหลด หากเขียนสำรองในเครื่องไม่สำเร็จจะไม่แทนที่ข้อมูล

ข้อมูลต้นฉบับฝังใน `index.html` เพื่อให้ยังใช้ HTML ไฟล์เดียวได้ ไฟล์ Excel ต้นฉบับไม่ถูกเผยแพร่

- Chromium ผ่านเซิร์ฟเวอร์ทดสอบในเครื่อง: จำนวนงาน/ยูนิต ตัวกรองระยะ รอยืนยันงาน/มูลค่า การติ๊กงานย่อยและบันทึกซ้ำ การเลือกเทมเพลต/ไม่สร้างซ้ำ CSV กู้คืน JSON มือถือ และ PDF
- Chromium: ข้อมูลแบบเก่ายังคงอยู่ก่อนเลือกโหลดแผน สำรอง JSON และสำรองในเครื่อง ย้อนคืนข้อมูลก่อนโหลดแผนได้ รีโหลดแล้วไม่สูญหาย และรายละเอียดงานย่อยถูกขยายขณะพิมพ์
- การตรวจเหล่านี้ยืนยันข้อมูลและพฤติกรรมในเครื่องทดสอบ ไม่ใช่หลักฐานว่า GitHub Pages เผยแพร่สำเร็จ
