# ใช้คนเดียวหลายเครื่องผ่าน Supabase

ส่วนนี้เป็นทางเลือก เว็บยังเปิดจาก HTML ไฟล์เดียวหรือ GitHub Pages ได้ ไม่ต้องติดตั้งแอปเพิ่มเติม การบันทึกออนไลน์ใช้ฐานข้อมูล Supabase ของคุณ ต้องตั้งค่าครั้งแรกก่อนจึงใช้งานข้ามเครื่องได้

## 1. สร้างฐานข้อมูล

1. เข้า [Supabase](https://supabase.com/dashboard) และสร้างโปรเจกต์ในบัญชีของคุณ เลือกแผนและภูมิภาคที่ต้องการ ตรวจเงื่อนไข/โควตาของบริการก่อนสร้าง
2. รอให้โปรเจกต์พร้อม แล้วเปิด **SQL Editor**
3. คัดลอกเนื้อหา [supabase/setup.sql](../supabase/setup.sql) ทั้งไฟล์ไปวาง แล้วกด Run หรือเปิดแอป → **ตั้งค่าเชื่อมต่อ → ดาวน์โหลด SQL ตั้งค่าฐานข้อมูล** จะได้ SQL ชุดเดียวกัน
4. ตรวจว่ารันสำเร็จ สคริปต์สร้างตาราง `site_checklist_projects` และฟังก์ชัน `save_site_checklist_project` ไม่มีการนำข้อมูลโครงการของคุณขึ้นฐานข้อมูลในขั้นนี้

## 2. สร้างบัญชีสำหรับคุณ

1. ในโปรเจกต์ Supabase เปิด **Authentication → Users → Add user / Create new user**
2. ใช้อีเมลและตั้งรหัสผ่านของคุณ เปิดตัวเลือกยืนยันอีเมลอัตโนมัติ (Auto Confirm User) หากแสดงอยู่ เพื่อให้บัญชีที่คุณสร้างเองเข้าสู่ระบบได้ทันที
3. ตรวจว่าผู้ให้บริการ Email/Password เปิดใช้งานอยู่ ชื่อเมนูอาจเป็น **Sign In / Providers** ใน Authentication
4. สำหรับการใช้คนเดียว สามารถปิดการสมัครผู้ใช้ใหม่จากภายนอกใน Authentication settings ได้ บัญชีที่สร้างจาก Dashboard จะยังใช้งานได้

เว็บไม่มีหน้าสมัครสมาชิก ลืมรหัสผ่านให้จัดการบัญชีของคุณผ่าน Supabase Dashboard ไม่ต้องส่งรหัสผ่าน รหัสฐานข้อมูล หรือคีย์ลับให้ผู้ช่วยในแชต

## 3. ตั้งค่าในแอปเครื่องแรก

1. หา **Project URL** และ **Publishable key** จากหน้า **Connect / API Keys** ของโปรเจกต์ หากใช้คีย์แบบเดิม ให้ใช้ **anon key** เท่านั้น
2. เปิดเว็บแอปเดิม → **ตั้งค่าเชื่อมต่อ**
3. กรอก URL รูปแบบ `https://PROJECT_REF.supabase.co` และ Publishable / anon key แล้วบันทึก แอปรองรับ URL มาตรฐาน Supabase Cloud ที่ใช้ HTTPS
4. กด **เข้าสู่ระบบ** ด้วยอีเมลและรหัสผ่านที่สร้างในขั้นก่อน
5. ตรวจข้อมูลโครงการในเครื่องนี้ว่าเป็นข้อมูลล่าสุด แล้วกด **บันทึกออนไลน์** ครั้งแรก
6. รอข้อความ **บันทึกออนไลน์สำเร็จ** และหมายเลขเวอร์ชัน ก่อนย้ายเครื่อง

ใช้เฉพาะคีย์สาธารณะ `sb_publishable_…` หรือ JWT anon key ห้ามใช้ `sb_secret_…`, service_role key หรือรหัสฐานข้อมูลในเว็บ คีย์สาธารณะใช้ระบุโปรเจกต์ ไม่ให้สิทธิ์เข้าถึงข้อมูลของคุณโดยไม่เข้าสู่ระบบ

## 4. เปิดจากมือถือหรืออีกคอมพิวเตอร์

1. เปิด URL เว็บแอปเดียวกัน
2. ตั้งค่า Project URL และคีย์สาธารณะเดียวกัน วิธีสะดวกคือเครื่องแรกกด **ตั้งค่าเชื่อมต่อ → ส่งออกการตั้งค่า** แล้วนำไฟล์ `site-checklist-connection.json` ไปใช้ปุ่ม **นำเข้าการตั้งค่า** ในเครื่องใหม่ จากนั้นกดบันทึก
3. เข้าสู่ระบบด้วยอีเมลและรหัสผ่านเดิม
4. กด **โหลดจากออนไลน์** เครื่องใหม่ไม่ส่งข้อมูลตัวอย่างทับออนไลน์เอง หากมีข้อมูลในเครื่อง ระบบจะถามก่อนแทนที่ และเก็บข้อมูลเครื่องนั้นสำรองไว้ก่อนโหลด
5. เมื่อแก้ไขเสร็จ กด **บันทึกออนไลน์** รอสำเร็จ จากนั้นอีกเครื่องกด **โหลดจากออนไลน์** ก่อนแก้ต่อ

รหัสผ่านไม่ถูกบันทึก โทเคนเข้าสู่ระบบเก็บใน sessionStorage ของแท็บนั้นเพื่อใช้งานระหว่างเปิดแท็บ การปิดแท็บ/ออกจากระบบอาจทำให้ต้องเข้าสู่ระบบใหม่ แต่ข้อมูลออนไลน์ยังอยู่ การส่งออก JSON ของโครงการและไฟล์การตั้งค่าไม่รวมรหัสผ่านหรือโทเคน

## ป้องกันข้อมูลทับกัน

- แต่ละบัญชีมีข้อมูลโครงการออนไลน์หนึ่งชุด (snapshot รวมทุกหลัง)
- การบันทึกใช้ revision ที่โหลดไว้ ฐานข้อมูลยอมรับเฉพาะเวอร์ชันปัจจุบันและเพิ่ม revision ครั้งละหนึ่งแบบ atomic
- ถ้าอีกเครื่องบันทึกใหม่ก่อน เครื่องเก่าจะได้รับข้อความปฏิเสธ ข้อมูลในเครื่องเก่ายังอยู่ ให้สำรอง JSON แล้วโหลดออนไลน์ ไม่ทำ last-write-wins
- ยังไม่มีการรวมข้อมูลจากสองเครื่องให้อัตโนมัติ หากแก้ทั้งสองเครื่องพร้อมกัน ให้ใช้ JSON เก็บการเปลี่ยนแปลงไว้ แล้วปรับงานที่ต้องการในเวอร์ชันล่าสุด
- หากแก้ข้อมูลเพิ่มระหว่างส่งข้อมูลขึ้นออนไลน์ ระบบเก็บเวอร์ชันที่ส่งและยังแสดงว่ามีการแก้ไขใหม่ที่ไม่ถูกส่ง
- เน็ตขาดหรือคำขอล้มเหลวไม่ได้ถือว่าบันทึกสำเร็จ ต้องดูข้อความยืนยัน หากคำขอหมดเวลา อาจต้องโหลดตรวจสอบผลก่อนบันทึกใหม่
- ก่อนโหลดออนไลน์ เก็บสำรองไว้ที่ localStorage อีกช่องหนึ่ง ปุ่ม **กู้คืนก่อนโหลดออนไลน์** คืนข้อมูลลงเครื่องเท่านั้น ยังต้องกดบันทึกออนไลน์เองหากต้องการส่งกลับ
- การแก้ไขในหลายแท็บของเบราว์เซอร์เดียวกันจะเตือนให้รีเฟรชก่อนใช้ปุ่มออนไลน์ เพื่อไม่ใช้สำเนาเก่าของข้อมูลในเครื่อง

## สิทธิ์ข้อมูล

SQL เปิด RLS และให้บัญชีอ่านได้เฉพาะแถวที่ `user_id = auth.uid()` บัญชีอื่นและผู้ที่ไม่เข้าสู่ระบบอ่านข้อมูลไม่ได้ ไม่มีสิทธิ์เขียนตารางโดยตรง การเขียนทำผ่านฟังก์ชันที่ตรวจบัญชีจริงจาก Auth และ revision เท่านั้น ฟังก์ชันใช้ SECURITY DEFINER โดยกำหนด search_path ว่าง อ้างอิงชื่อตารางเต็ม และไม่รับ user_id จากไคลเอนต์

ข้อมูลโครงการที่แก้ไขจะถูกส่งไป Supabase ของคุณเฉพาะเมื่อกดบันทึกออนไลน์ ไม่ถูกส่งกลับ GitHub อย่างไรก็ตาม ข้อมูลแผน R3 ตั้งต้นยังฝังใน HTML สาธารณะตามเดิม การออกจากระบบไม่ล้างข้อมูลโครงการที่บันทึกในเครื่อง หากใช้เครื่องร่วมกับผู้อื่นควรจัดการข้อมูลเบราว์เซอร์แยกกัน

## ขอบเขตการทดสอบ

ทดสอบผ่าน Chromium ด้วยสองอุปกรณ์จำลองครอบคลุมการบันทึก/โหลด การป้องกันเวอร์ชันชนกัน การสำรองก่อนโหลด การกู้คืน เน็ตขาด การรีเฟรช session และการแก้ไขระหว่างส่งข้อมูล ทดสอบ SQL ใน PostgreSQL แบบฝังด้วย PGlite ครอบคลุม RLS, anonymous access, การห้ามเขียนตรง, ข้อมูลไม่ถูกต้อง และการแข่งบันทึก revision เดียวกัน

ยังต้องตรวจจริงกับโปรเจกต์ Supabase ที่คุณสร้าง: เครื่องแรกบันทึกจนสำเร็จ แล้วอีกเครื่องเข้าบัญชีเดียวกันและโหลดเห็นข้อมูลตรงกัน จึงยืนยันการใช้งานออนไลน์จริงได้
